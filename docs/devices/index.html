Two apps

  • Contour 1.3.3 (stable)The released app. It supports the CrinEar Protocol Micro 3302:C20F, the CrinEar Protocol Max 3302:43CC and the FiiO KA15 2972:0104, all tested on real hardware.Contour 1.3.3 release on GitHub
  • Contour advBeta 1.3.3-advbeta1A separate experimental build that adds support for many more devices. Most of them have never been seen on real hardware, so this list says exactly which, and your reports are how they get verified.advBeta 1.3.3-advbeta1 release on GitHub

Writing to a device that is not marked Verified is at your own risk. Read the current EQ first and keep a backup profile. A device moves to Confirmed on hardware after a report the maintainer has checked.

Help

Find your VID:PID

Contour does not show it, so here is how to look it up.

Contour does not show the VID:PID or the USB name of a plugged-in device. Its service screen (long-press the status pill in the Library) shows the model name Contour matched, and a short log, but only for a device it already recognises. For an unknown device it tells you nothing, so use one of these instead:

  • On Android: install a USB device info app, plug the DAC in through OTG and open its entry. Look for the vendor ID, the product ID and the product name. Hex values are usually shown as 0x3302 and 0xC20F, which is 3302:C20F here.
  • On Windows: Device Manager, open the device, Details tab, Property: Hardware Ids. You will see VID_3302&PID_C20F.
  • On Linux: run lsusb; the ID column reads 3302:c20f. lsusb -v adds the product name.
  • On macOS: Apple menu, About This Mac, System Report, USB. Vendor ID and Product ID are listed per device.

Copy the USB product name exactly as shown, including any extra spaces: some names carry a trailing or double space, and Contour compares them character by character.

How matching works

Why the name on this page may not equal what your device reports.

  • The WalkPlay catalog pairs are matched by vendor and product ID. The USB name the device reports can be any non-empty name; the label on this page is only the display name.
  • Three exceptions: if the reported name equals one of the WalkPlay name rules, that rule's scheme, bands and filter types win over the catalog row (a scheme-11, 8-band pair that reports Octave is written as scheme 18 with 10 bands). If it equals a name handled by another family, or a KT Micro name, the pair is blocked. Pairs marked blocked or exact-name-only keep their own conditions.
  • The WalkPlay name rules match the USB name on any product ID of 19 vendor IDs, and writing through them needs no extra confirmation beyond the normal checks (HID descriptor check, complete read before write, hold to send).
  • FiiO name rules, the Moondrop names and the KT Micro name CDSP also match on any product ID, and ask for a tap on Connect first.
  • Rules that match by name on any product ID are not in the Android USB attach filter. Plugging the device in does not launch Contour; they are found only while the app is open.
  • DAWN PRO2 and DAWN PRO 2 are different devices: the first is Moondrop read-only, the second is a WalkPlay write-enabled name.

Known issues

  • A blocked KT Micro name currently shows a misleading message ("KT Micro requires its separate driver"). The device is blocked on purpose; the text is wrong. The same message appears for a KT Micro name on product IDs 0001, 1132, 3006 and 3016.
  • In advBeta, the Moondrop, FiiO, KT Micro and Fosi checks run before the Protocol Micro and Max shortcuts. A Micro or Max that reports a deliberately odd name, such as FIIO FX17 or a Moondrop name, leaves the Micro or Max path. Normal devices are not affected.
  • Wide recognition is deliberate: advBeta would rather offer a read to an unknown device than ignore it. That is why you should read first and keep a backup before any write.
